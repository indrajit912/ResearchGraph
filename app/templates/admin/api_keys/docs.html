Superadmin REST API Documentation

Version: v1

Authentication

All API requests must be authenticated using an API key passed in the Authorization HTTP header as a Bearer token.

Authorization: Bearer rg_abcdefgh_your32charsecret

Note: Your API key will only work if you currently have the SUPERADMIN role.

Endpoints

Retrieves the complete public research-network graph of all active researchers.

Response
{
  "data": {
    "nodes": [ { "id": "...", "display_name": "..." } ],
    "links": [ { "source": "...", "target": "...", "status": "ESTABLISHED" } ]
  },
  "meta": {
    "total_nodes": 150,
    "total_links": 300
  }
}

List researchers with pagination and optional search.

Query Parameters
  • q (string): Search term
  • page (int): Page number (default: 1)
  • page_size (int): Results per page (default: 20, max: 100)

Retrieves the profile of a single researcher by their slug.

Retrieves the local research network (collaborators) for a single researcher.

Updates a researcher's basic profile information.

Request Body (JSON)

Send a partial JSON object with the fields you wish to update.

{
  "department": "Computer Science",
  "is_active": true
}

Deletes a researcher and cleans up associated reports and edges to prevent graph orphans. Returns 204 No Content on success.

Triggers a secure, programmatic physical database backup. The response body is the raw binary stream of the SQLite .db file.

Performs a highly destructive, instant programmatic overwrite of the production database.

Safety Headers

You MUST include the HTTP header X-Confirm-Restore: true. Without this, the request is immediately rejected.

Request Format

Must be multipart/form-data with the file attached under the key db_file.
